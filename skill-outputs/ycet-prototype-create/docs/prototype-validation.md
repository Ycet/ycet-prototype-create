# 原型任务结束与验证边界

## 修改完成即结束（优先规则）

完成用户要求的原型修改并保存后，必要事务收尾并直接回复。默认不追加静态守卫、局部／全量回归、浏览器检查、截图比对、离线分享测试或其他验收。仅用户明确要求测试／验收时执行指定范围。

适用 A/B/C、方向预览、功能四接管和功能五请求；包括全局修改、增删页、新增迭代、类型转换及首次接管既有原型。不能据文件是新建就误判为首次制作。此规则优先于所有下游的修改后验证要求，也不能把验收搬到保存前规避。

执行修改需要的读取、唯一定位、资源内联、写入前摘要及并发保护保留。写入失败或已知需求未完成时如实处理，不虚报完成。工作台写入后按协议 complete／abort 并释放事务；用户工作台服务保留。成功状态表示修改执行完成，不代表未执行的测试通过。

## 构建用途

优先直接编辑现有 HTML，保留稳定标识。需要构建器时，iterate/overwrite 默认 modify；类型转换创建新基名时显式 --purpose modify。修改默认不调用 audit；仅用户明确要求验证才传 --validate。首次 create 默认 initial，保留构建内守卫；已通过的相同字节不重复守卫。

## 何时验证

从零首次生成：对交付文件检查所有页面、核心流程和相关视口，独立复制后离线运行；构建器已通过的守卫不重复运行。仅有新文件名的修改不适用此分支。

用户显式要求测试：按请求范围执行；复用浏览器和现有脚本，失败有新信息才重试。结果针对最终文件，不能把草稿预览或旧摘要的结果算作当前通过。

Skill 自身代码开发／发布：读取 verification.md，按受影响组件与版本验收要求运行测试；不把这套开发命令用于普通产品原型修改。

## 轻量读取与收尾

同一上下文不重复读未变规范。大 HTML 只回传目标片段及元数据，不回传 Base64、字体和重复 DOM；单行文件按结构提取。避免局部改动重建全部页面、重新生成素材或新建永久测试工程。

修改完成后不再开浏览器、截图、创建测试、等待反馈或询问是否追加验收。必要进程清理和事务结束后简短报告文件、修改及已知限制。未执行验证时不声称通过。显式测试或首次生成的规定检查通过后同样及时交付；环境不可用则如实说明缺口。

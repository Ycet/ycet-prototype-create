# 功能四：HTML 或图片原型规范化重构与编辑

## 目标

接管非本 skill 生成的 HTML 或图片原型，先规范化为本 skill 的原型结构，再根据用户要求编辑。

凡涉及原型 HTML 或图片承载页面写入/修改，必须按 `shared-editlog-rules.md` 记录。

## 输入类型

| 输入 | 处理方式 |
| --- | --- |
| HTML 原型 | 先做合规性审计，再分级重构与编辑 |
| 图片原型（png、jpg、jpeg、webp 等） | 保存到 `prototype/pages/`，提醒用户手动重命名，确认后生成承载页面和 `index.html` |

## HTML 原型处理流程

1. 读取 `shared-prototype-standards.md` 与 `shared-editlog-rules.md`。
2. 审计原 HTML 是否符合本 skill 规范。
3. 向用户展示审计结果和建议重构等级。
4. 按等级执行规范化重构。
5. 再按用户要求编辑重构后的原型。
6. 分别记录“规范化重构”和“用户要求的编辑”到 `EditLog.md`。

## 分级重构

| 等级 | 适用情况 | 允许动作 |
| --- | --- | --- |
| Level 1 轻量接管 | 原页面视觉和结构基本正常 | 迁移到 `prototype/pages/`，补齐 `index.html`、设备框架、尺寸和 EditLog |
| Level 2 结构修复 | 页面内容保留，但嵌入 iframe 不稳定 | 调整根容器、滚动容器、状态栏/导航栏位置、iframe 防溢出样式 |
| Level 3 规范化重写 | 原 HTML 严重不合规或无法稳定嵌入 iframe | 在页面内容、文案、功能表达不变的前提下重写 HTML/CSS |

Level 3 必须在用户确认后才能执行。

## 图片原型处理流程

1. 将图片保存到 `prototype/pages/`。
2. 提醒用户手动重命名为清晰的英文文件名。
3. 用户确认重命名完成后，生成 `prototype/index.html`。
4. 将 `prototype/pages/` 下图片添加到设备框架中展示。
5. 图片必须完整展示内容，不被设备框架截断且无留白。
6. 若图片长于设备框架，必须支持在设备框架内部上下滑动，模拟页面滚动。
7. 记录“导入图片原型资源”和相关 HTML 写入。

## 审计维度

- 是否位于 `prototype/` 结构内；
- 是否有独立 `pages/` 页面；
- 页面根容器尺寸是否匹配端口；
- iframe 是否会出现原生滚动条；
- 是否存在文档级横向溢出；
- 状态栏、导航栏、滚动容器是否合理；
- 页面内容是否可在设备框架中完整展示；
- 是否已有或需要创建 `EditLog.md`。

## 完成标准

- HTML 或图片原型已纳入 `prototype/` 结构。
- 页面可以通过 `prototype/index.html` 在设备框架中查看。
- 用户要求的编辑已完成。
- `EditLog.md` 已记录规范化和编辑动作。

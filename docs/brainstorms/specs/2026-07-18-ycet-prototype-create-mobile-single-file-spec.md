# Agent 交接摘要

- 目标：为 `ycet-prototype-create` 增加功能五，将已确认的多页面交互原型打包为可单独发送到手机、脱离项目目录且断网可运行的 `prototype-mobile*.html`。
- 已确认方案：使用一个铺满手机浏览器可视区域的无边框 `iframe srcdoc` 加载内嵌运行时页面；页面、样式、脚本、图片、图标、字体及其他必要资源全部内联；默认隐藏预览导航，通过按钮展开左侧导航抽屉。
- 范围边界：功能五负责输入审计、交互确认门禁、缺失时的运行时准备、确定性单文件打包、只读保护和移动端验收。完全缺少运行时页面时，经用户确认可新建 `runtime-pages/`；已有运行时页面及其他原型文件一律只读。
- 明确不做：不修改既有 `runtime-pages/*.html`、`pages/*.html`、`index.html`、`prototype.html`、框架或资源文件；不生成设备外壳；不依赖网络；不静默修复不完整运行时产物；不创建或修改 `prototype.html`。
- 验收标准摘要：单个输出文件可在脱离项目目录和断网情况下运行；页面交互与功能三 Demo 一致；导航抽屉、浏览器返回、资源内联和路径安全可用；生成前后受保护输入的文件集合与 SHA-256 不变。
- 待决问题：无。
- 相关计划：`../plan/2026-07-18-ycet-prototype-create-mobile-single-file-plan.md`

# 背景与目标

## 背景

现有功能三通过 `prototype.html`、`runtime-pages/*.html` 和设备框架组成桌面端交互 Demo。该结构适合在项目目录内检查和演示，但不能只把一个 HTML 文件发送到手机后直接预览，因为页面和资源仍分布在多个目录与文件中。

用户需要新增功能五，将功能三的运行时页面和交互逻辑集成为真正离线的单一 HTML 文件。原需求中的 `runtimes-pages/` 统一更正为现有规范目录名 `runtime-pages/`。

## 目标

1. 在 Skill 路由和默认功能菜单中增加功能五。
2. 根据已有 `runtime-pages/*.html` 和 `prototype.html`，或经确认后新建的运行时页面，生成 `prototype-mobile.html` 或递增版本。
3. 让最终文件单独传输到手机后，无需项目目录、网络或其他文件即可预览全部页面和交互。
4. 默认以接近真实 App 的方式全屏展示页面，同时提供按需展开的页面导航工具。
5. 保持功能三既有交互协议和业务跳转，不修改已有原型输入。

# 用户场景

1. 用户已有完整 `prototype.html` 和 `runtime-pages/*.html`，要求生成可发送到手机的单文件预览。功能五直接复用现有页面注册表和交互逻辑，不再询问。
2. 用户只有完整 `runtime-pages/*.html`，要求手机预览。功能五从运行时页面提取页面清单和跳转关系，不再询问。
3. 用户只有 `prototype.html`，但缺少运行时页面。功能五展示推导出的跳转图，用户确认后创建全新运行时页面，再打包手机文件。
4. 用户只有静态 `pages/*.html`。功能五根据页面、Spec 和当前对话整理跳转图，用户确认后创建全新运行时页面，再打包手机文件。
5. 用户把 `prototype-mobile*.html` 单独发送到手机，在断网状态下打开，使用原型内部交互浏览页面；需要快速检查其他页面时，通过菜单按钮展开左侧导航抽屉。
6. 用户重复生成功能五产物时，保留已验证的旧文件并获得新的递增版本。

# 已确认需求

1. 新增功能五，调用场景为用户需要制作可在手机上预览的原型或生成移动端离线单文件。
2. `SKILL.md` 默认选择菜单增加选项 E：生成手机端离线单文件原型，对应 `docs/function-5-mobile-single-file.md`。
3. 用户明确提到手机预览、移动端预览、单 HTML、单文件离线预览或 `prototype-mobile.html` 时直接路由到功能五。
4. 功能五首次输出 `prototype/prototype-mobile.html`；后续依次输出 `prototype-mobile-v2.html`、`prototype-mobile-v3.html`，不得覆盖已有版本。
5. 最终文件必须是真正离线的单文件，内联页面 HTML、CSS、JavaScript、图片、图标、字体及必要的其他资源。
6. 手机打开后，当前页面默认铺满浏览器可视区域，不显示功能三的左侧导航、设备框架或调试信息。
7. 外层提供菜单按钮，可按需展开左侧页面导航抽屉；抽屉属于预览工具，不属于产品页面，也不写入运行时页面。
8. 原型内部交互是主要跳转方式；移动端外壳继续使用功能三消息协议和页面注册表处理跳转。
9. `prototype-mobile*.html` 使用单个全屏无边框 `iframe srcdoc` 加载当前内嵌页面，保证页面 CSS、DOM ID 和脚本彼此隔离。
10. 已有 `runtime-pages/*.html`、`pages/*.html`、`index.html`、`prototype.html`、框架和资源文件均为只读输入。
11. 完全缺少可用运行时页面时，功能五必须先获得用户对页面跳转逻辑的明确确认，随后才可新建 `runtime-pages/` 及页面。
12. 已存在的运行时页面不得覆盖、格式化、补写、修复或重命名。运行时页面部分缺失或相互冲突时停止，不混合新旧页面。
13. 功能五不创建、不修改 `prototype.html`。缺少运行时页面时的创建属于功能五内部的运行时准备阶段，不自动切换或要求另行调用功能三。
14. 单文件打包由专用确定性脚本执行；Skill 负责交互门禁、运行时准备、输入保护和验收流程。
15. 任何无法完整内联的关键依赖都必须阻断生成，不得静默删除功能、保留远程依赖或交付半成品。

# 方案比较与最终决策

## 方案 A

- 做法：将每个运行时页面转为自包含 `srcdoc` 文档，外层使用单个全屏 iframe 和内嵌页面注册表切换页面。
- 优点：页面隔离良好；现有 `window.parent.postMessage()` 可由移动端外壳接收；不需要合并或重写页面 CSS、DOM 与脚本。
- 代价/风险：必须完整内联资源并正确处理 HTML、JSON 和脚本转义；页面切换会重建文档。

## 方案 B

- 做法：把全部运行时页面合并为同一 DOM 下的多个隐藏容器，通过显示和隐藏切换页面。
- 优点：结构直观，切换时无需重新创建 iframe 文档。
- 代价/风险：页面 CSS、全局变量、DOM ID 和事件监听器容易冲突，通常需要改写现有运行时页面，违反只读和等价交互目标。

## 方案 C

- 做法：把内嵌页面和资源转换为 Blob URL，再由全屏 iframe 加载。
- 优点：页面仍保持独立 URL 和文档隔离。
- 代价/风险：移动端浏览器对本地 `file://`、Blob、脚本和资源加载存在更多兼容差异，还需管理 Blob URL 生命周期。

## 最终决策

采用方案 A：单个全屏 `iframe srcdoc` 加内嵌页面注册表。所有资源打入 `prototype-mobile*.html`，外层只负责预览工具、页面切换、历史和消息校验，不修改内嵌页面业务逻辑。

# 设计说明

## 核心流程

### 1. 路由

- 明确的手机预览或单文件离线预览意图直接进入功能五。
- 无法直接路由时，在默认功能菜单中提供选项 E。
- 单次任务始终属于功能五；缺少运行时页面时在功能五内部执行运行时准备。

### 2. 输入审计与状态矩阵

| `runtime-pages/*.html` | `prototype.html` | 处理方式 |
| --- | --- | --- |
| 完整有效 | 完整有效 | 以 `prototype.html` 的页面注册表、顺序和目标映射为主，核对运行时页面，无需再次确认 |
| 完整有效 | 不存在 | 从运行时页面的 `data-ycet-nav-target`、`navigate` 消息和页面元数据提取交互图，无需再次确认 |
| 不存在 | 存在 | 读取页面注册表作为参考，展示跳转图并请求确认；确认后创建运行时页面 |
| 不存在 | 不存在 | 从 `pages/*.html`、Spec 和当前对话整理跳转图；确认后创建运行时页面 |
| 部分存在、目标悬空或两类产物冲突 | 任意 | 停止并列出问题，不自动补齐或选择其中一方 |

### 3. 运行时准备

1. 仅在完全没有可用运行时页面时进入。
2. 展示页面跳转图并取得用户明确确认。
3. 对 `pages/*.html`、`index.html`、已有 `prototype.html` 及相关既有输入建立原始字节 SHA-256 快照。
4. 复用功能三的运行时副本、路径和消息协议规范，创建全新的 `runtime-pages/*.html`。
5. 验证受保护输入文件集合和摘要未变化。
6. 不生成 `prototype.html`。
7. 运行时准备完成后，重新建立功能五打包阶段的只读基线。

### 4. 注册表和初始页

初始页按以下优先级确定：

1. `prototype.html` 明确登记的初始页面；
2. `index.html` 页面清单中的第一个有效运行时页面；
3. 文件名对应 `home` 的运行时页面；
4. 运行时页面注册表的第一个页面。

无法得到唯一有效初始页时停止并请求确认。

### 5. 资源发现和内联

从每个运行时页面递归收集并处理：

- 本地 CSS、CSS `@import` 和 `url()`；
- 本地 JavaScript、模块依赖和静态可枚举 import；
- 图片、`srcset`、SVG、图标和背景图片；
- 本地字体和字体 CSS；
- 页面直接引用的音频、视频、JSON、WASM 和嵌套本地文档。

所有相对路径先按原运行时页面目录解析。CSS 转为内联 `<style>`，脚本转为内联脚本，二进制资源按正确 MIME 类型转为 Data URL 或等价内嵌记录。相同资源应尽量去重。最终 `srcdoc` 不得读取项目文件或网络。

页面内容写入外层脚本或 JSON 时，安全处理 `</script>`、引号、反斜杠和 Unicode 分隔符，避免破坏外层文档。

### 6. 单文件构建

1. 专用脚本读取已准备完成的运行时页面和有效注册表。
2. 生成自包含页面数据、资源数据和目标映射。
3. 构造全屏页面容器、预览工具层、导航抽屉和历史管理。
4. 首次选择 `prototype-mobile.html`，后续选择下一个 `prototype-mobile-vN.html`。
5. 在临时位置构建并完成全部静态校验。
6. 校验成功后原子写入最终文件；失败时不留下半成品，不改变已有手机版本。
7. 复核打包阶段受保护输入未变化。

### 7. 手机端运行

- iframe 使用固定定位铺满可视区域，优先 `100dvh` 并提供 `100vh` 回退。
- 页面避让浏览器安全区，但不绘制设备系统 UI。
- 左上角固定菜单按钮位于预览工具层，点击后展开覆盖式左侧导航抽屉。
- 抽屉显示页面名称、顺序和当前页高亮，不显示路径、日志或调试信息。
- 选择页面、点击遮罩或关闭按钮后收起抽屉；抽屉不缩放当前页面。
- 滚动、弹窗、表单和其他页面内交互由当前 `srcdoc` 页面自行处理。

### 8. 页面跳转和历史

- 内嵌页面继续发送 `channel: "ycet-prototype"`、`version: 1` 的 `navigate` 消息。
- 外层验证消息来源、channel、version 和目标注册表。
- 合法目标切换到对应 `srcdoc`；未知、远程、绝对、上级目录和 `javascript:` 目标被拒绝，并保留当前页面。
- 抽屉页面选择复用同一注册表，不建立第二套目标映射。
- 内部页面历史栈与同文件 `history.pushState()` 同步。
- 手机浏览器返回操作优先返回原型上一页；内部历史为空时不阻止浏览器默认行为。
- 页面返回时重建对应 `srcdoc`，默认不恢复已销毁页面的瞬时 DOM 状态。

## 数据与状态

### 页面注册表

每个页面至少保存：

- 稳定页面 ID；
- 用户可读页面名称；
- 原始静态 pathname；
- 原始运行时 pathname；
- 内嵌 `srcdoc` 内容或安全引用；
- 已登记跳转目标；
- 页面顺序；
- 是否为初始页面。

### 资源注册表

每个资源至少保存：

- 规范化项目内源路径；
- MIME 类型；
- 内容摘要；
- 内嵌内容；
- 使用页面集合。

同一摘要资源应尽量复用，避免无意义重复。

### 运行状态

- 当前页面 ID；
- 页面历史栈；
- 导航抽屉开关状态；
- 已创建的资源 URL 或内嵌映射；
- 最近一次可识别运行时错误。

不持久化页面瞬时 DOM 状态。

## 错误处理与边界情况

以下情况阻断生成并报告文件、位置、原因和建议处理方式：

- `prototype/` 或静态页面不存在；
- 运行时页面部分缺失、交互目标悬空或与 `prototype.html` 冲突；
- 需要确认的交互图尚未获得确认；
- 无法确定唯一初始页；
- 页面或资源路径越界；
- CSS、脚本、图片、字体或其他本地资源缺失；
- 无法枚举的动态 import、运行时拼接资源或关键网络依赖；
- 依赖登录态、Cookie、服务器重定向或真实后端；
- MIME 类型无法确定或资源读取失败；
- 快照、输出版本选择、临时构建或原子写入失败；
- 目标浏览器无法稳定加载最终文件。

运行时收到非法或未知页面目标时保留当前页面，并显示可识别的预览错误，不跳转到远程或空白地址。

# 验收标准

## 路由与流程

- 默认选择菜单显示功能五选项 E。

- 不覆盖任何已有手机版本。
- 除经确认新建的运行时页面和最终手机版文件外，不写入项目文件。
- 打包阶段前后受保护文件集合和 SHA-256 完全一致。
- 失败时没有半成品最终文件，已有版本保持不变。

## 单文件与离线

- 最终交付仅需一个 HTML 文件。
- 文件不含项目绝对路径、`file:///`、运行时本地相对资源读取、HTTP/HTTPS 或 CDN 依赖。
- 每个页面和目标均存在于内嵌注册表。
- CSS、脚本、图片、图标、字体和必要资源均可从文件内部恢复。
- 文件单独复制到带中文和空格的项目外目录后可打开。
- 断网后全部原型页面和交互仍可使用。
- 完成说明记录集成页面数量、资源类型与数量、最终文件大小和未验证项。

## 手机端交互

- 初始页面正确并铺满手机浏览器可视区域。
- 默认不显示设备框架、常驻导航或调试信息。
- 菜单按钮、左侧抽屉、遮罩关闭、页面选择和当前页高亮可用。
- 原型内部跳转与功能三既有 Demo 一致。
- 浏览器返回键按内部页面历史返回，历史为空时交还浏览器。
- 页面滚动、弹窗、表单、热区和页面内交互可用。
- 竖屏与横屏切换后仍覆盖可视区域。

## 安全与兼容

- `srcdoc` 和外层数据安全转义，不被页面内容破坏。
- 外层验证 postMessage 来源、channel、version 和目标注册表。
- 拒绝远程 URL、绝对路径、目录穿越、控制字符和 `javascript:`。
- 打包脚本不执行用户原型脚本，只解析和序列化；脚本仅在受控浏览器验收时运行。
- Chrome Android、Edge Android、Safari iOS 记录实际测试结果；无法实际运行的目标明确标记未验证，不以桌面模拟冒充真机通过。
- 不设置固定体积阈值；若实际目标浏览器无法稳定加载，则验收失败。

## 自动测试

至少覆盖：

- 多页面导航和注册表目标；
- 导航抽屉与浏览器返回；
- CSS、JavaScript、图片、图标和字体内联；
- 中文、空格、query/hash 页面路径；
- 缺失资源、远程依赖和路径越界阻断；
- `</script>`、引号、反斜杠和 Unicode 安全转义；
- 重复生成版本递增；
- 受保护输入 SHA-256 不变；
- 单个输出文件脱离项目目录和断网运行。

# 风险与约束

1. Data URL 和多页面内容会增加文件体积与内存占用；不得用删除资源或降低功能完整性换取体积。
2. `srcdoc` 页面切换会重建页面，默认不保留瞬时页面状态。
3. 动态资源路径、真实后端和登录态无法保证离线打包，必须阻断或先由用户调整原型。
4. Safari iOS 对本地文件、内联脚本、历史和大文件的行为可能与桌面浏览器不同，必须记录真机验证状态。
5. 资源去重、模块内联和安全转义属于高风险机械流程，应由确定性脚本和回归测试保障。
6. 功能五只能复用功能三协议，不得另建不兼容的导航消息格式。
7. 现有工作区可能包含与功能五无关的修改，后续实现不得回退或混入这些变更。

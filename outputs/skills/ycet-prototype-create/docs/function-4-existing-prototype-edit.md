# 功能四：现有 HTML 或图片原型规范化与编辑

## 目标

接管非本 Skill 生成的 HTML 或整页图片原型，按 Manifest 驱动的新框架体系完成源码解析、静态重构和经确认的交互化。Level 1/2/3 只决定源码复用强度，不得绕过 Spec、UI 方向、静态交付或交互确认门禁。

开始前读取 `shared-prototype-standards.md`、`shared-editlog-rules.md` 与 `../assets/frames/manifest.json`。

- HTML 分支通过产品端口门禁后读取 `function-1-static-prototype.md`，但跳过其阶段一输入分类与外部需求 Skill，只复用 Spec 字段、阶段二和阶段三。
- `function-3-interactive-demo.md` 只能在静态产物完成且用户再次明确确认后读取和执行，不得提前加载后预生成交互产物。

## 产品端口确认门禁

本门禁优先于原型读取、审计、导入、框架选择和文件写入。每次启动功能四时，必须先向用户询问一遍：

> 当前产品原型是什么产品端口？请选择 iOS/iPhone、Android、iPad、网页/网站、桌面端/Windows/macOS 或微信小程序；若为微信小程序，请同时说明宿主设备，或明确答复“使用默认宿主”。

即使用户的初始描述、文件名或已有配置看似已经表明端口，也必须重新询问并获得明确回复。不得通过现有 HTML、图片内容、画布尺寸、系统 UI、文件名、目录名、Spec、`index.html`、旧框架、`frame-config.json` 或其他元数据自行判断、替用户确认或覆盖用户回复。用户明确回复前，不得开始读取或审计用户原型，不得决定重构等级，不得导入资源、选择或复制框架，也不得生成或修改文件。

用户明确回复后，只能按与功能一完全一致的规则从 Manifest 选择设备框架：

| 产品端口 | 设备框架 |
| --- | --- |
| iOS、iPhone | `iphone-15-pro` |
| Android | `android-pixel` |
| iPad | `ipad-pro` |
| 网页、网站 | `browser-chrome` |
| 桌面端应用、Windows、macOS | `macbook` |
| 微信小程序 | 默认 `iphone-15-pro`；用户明确指定 Android 宿主时使用 `android-pixel` |

若用户选择微信小程序但未说明宿主设备或“使用默认宿主”，继续询问并等待回复；若回复包含多个端口或含义不明确，先确认本次任务对应的唯一端口。现有原型与用户确认端口不一致时，只将差异作为后续审计证据，不得改用推断端口。

## 输入类型

| 输入 | 处理方式 |
| --- | --- |
| 非本 Skill HTML 原型 | 产品端口确认 → 解析源码及关联文件 → 直接生成并确认 Spec → 功能一阶段二/三 → 停止 → 用户确认后进入功能三 |
| PNG/JPG/JPEG/WebP 等整页图片 | 产品端口确认 → 原图承载型 `pages/` 页面与 `index.html` → 停止 → 用户确认后生成 `prototype.html` |

## HTML 审计

检查：

- 入口 HTML、其他页面 HTML、CSS、JavaScript、字体、图片和模块依赖的文件清单及引用关系；
- 页面清单、页面元素、页面内状态交互、跨页面流程、业务规则、异常分支及用户要求新增或修改的内容；
- 是否位于 `prototype/` 结构内；
- 是否存在独立 `pages/` 页面；
- 是否存在 `frame-config.json`；
- 项目配置、`index.html` 和 Manifest 是否一致；
- 框架文件是否存在并支持 `screen` 协议；
- 页面根画布是否匹配逻辑尺寸；
- 页面是否重复绘制系统 UI；
- 安全区域、滚动容器和产品固定导航是否合理；
- iframe 是否溢出、裁剪、留白或出现原生滚动条；
- `index.html` / 设计预览中框架 iframe 是否等于项目 `preview` 固定像素，是否被百分比或二次 scale 压扁；
- 是否存在外链内容图（如 `img[src^="http"]`）或 CSS 远程内容背景图；
- 是否存在远程图标 CDN / 远程 SVG 图标依赖；
- 是否用灰色占位或图标冒充内容图；
- 本地图片/图标相对路径是否指向存在文件；
- 本地样式、脚本、字体、`srcset`、CSS `url()` / `@import` 和模块 import 是否在迁移后仍指向存在文件；
- 是否存在 EditLog。

### 新框架配置异常

- 配置缺失：只根据门禁中用户已确认的产品端口与 Manifest 得到候选框架；`index.html`、框架文件名和 Spec 仅作为一致性审计证据，不得用于推断产品端口。
- 配置无效或与 `index.html` 冲突：列出差异，不静默覆盖。
- Manifest 或框架文件缺失：报告并停止新框架迁移。

### 旧框架

识别 `.phone-frame`、`.android-frame`、`.miniapp-frame`、`.browser-frame`、`.desktop-frame` 等旧结构。旧尺寸只用于理解当前页面，不写入新 Manifest。

## 分级重构

| 等级 | 适用情况 | 允许动作 |
| --- | --- | --- |
| Level 1 轻量接管 | 源码结构和页面表达基本可复用 | 复用合规内容与结构，重写受迁移影响的路径并接入新框架 |
| Level 2 结构修复 | iframe 不稳定、系统 UI 重复或页面结构需调整 | 修复逻辑画布、滚动、安全区域、系统/产品 UI 边界和框架引用 |
| Level 3 规范化重写 | 严重不合规或无法稳定复用 | 按已确认 Spec 与 UI 方向重写 HTML/CSS，保持未授权业务内容和流程不变 |

三个等级都必须走下文的 Spec → 功能一阶段二 → 功能一阶段三流程；等级不能作为跳过步骤的理由。建议等级写入 Spec，Level 3 最迟在静态实现计划门禁时获得用户明确确认。

## 非本 Skill HTML 原型编辑流程

本流程适用于用户要求增加交互、增加页面、修改交互、修改页面或进行其他编辑的非本 Skill HTML。即使只修改一个页面，也必须先完成解析重构，不得直接在源文件上局部改写后交付。

### A. 源码解构与直接生成 Spec

1. 执行产品端口确认门禁并等待用户明确回复，根据 Manifest 获得唯一设备框架。
2. 以用户提供的入口 HTML 为起点，读取其引用的其他 HTML、CSS、JavaScript、字体、图片和模块文件；建立入口、页面、资源与脚本关系清单。只根据实际代码和可验证行为分析，不得编造缺失逻辑。
3. 解构并记录现有页面、页面元素、页面内交互、跨页面流程、业务规则、异常状态、资源依赖，以及用户要求新增或修改的页面与交互。
4. 完成合规审计，给出最低必要重构等级及证据。缺失或无法读取的关联文件写入“待确认事项”，不得用推测补齐。
5. 直接生成 `prototype/docs/Spec.md`。本分支不得调用 `brainstorming-solo` 或 `grill-me`，也不得转入功能一阶段一的提问流程。
6. Spec 至少包含：产品端口、宿主设备、框架 ID、源码文件清单、现有页面清单、目标页面清单、页面元素、功能说明、页面内交互、页面间流程、业务规则、异常与边界、用户要求的变更、源码到新页面的映射、建议重构等级和待确认事项。
7. 原 HTML 的视觉样式只作为“源视觉证据”或“阶段二待处理输入”记录，不得在 Spec 中自动确定为重构后的 UI 设计风格。
8. 生成后展示 Spec 摘要并请求用户确认；用户确认 Spec 前不得进入功能一阶段二。Level 3 可与 Spec 一并确认，但不能静默视为已确认。

### B. 复用功能一阶段二与阶段三

1. Spec 确认后进入功能一阶段二，按其规则发现/选择 UI Skill，或依次确认参考对象、设计风格、色彩方案和补充要求。源 HTML 的视觉风格只能作为候选参考，不能替用户作出选择。
2. 生成并确认 `design-direction.html` 与首页预览后，执行功能一阶段三的实现计划门禁。
3. 按已确认 Spec、UI 方向和用户编辑要求生成新的静态高保真 `pages/**/*.html` 与 `index.html`。页面内交互可以实现；跨页面交互只保留 `data-ycet-nav-target`，不得在静态页执行跳转。
4. 迁移源码时，以原文件 URL 为基准解析本地 `src`、`srcset`、`href`、CSS `url()` / `@import` 和模块 import；移动后改写为项目内相对路径并逐项验证。外链内容图与远程图标按共享规范本地化。
5. 运行功能一静态交互校验并完成其全部验收标准；分别记录源码解析重构、UI 方向、静态生成和用户要求的编辑。

### C. 静态完成后的功能三强门禁

- 静态高保真原型完成后必须停止当前任务，展示 `Spec.md`、设计方向、`pages/**/*.html` 与 `index.html` 的完成情况，并单独询问用户是否确认继续生成可交互原型。
- 用户在任务开始时提出“增加交互”“修改交互”或“最终需要可交互原型”，不得视为此处的确认；必须在静态产物完成后再次获得明确回复。
- 用户明确确认前，禁止创建 `runtime-pages/`、`runtime-assets/`、`prototype.html` 或其他 `prototype*.html`，也不得提前向静态页注入跨页逻辑。
- 只有用户明确确认生成可交互原型后，才读取并完整执行功能三；先对 `index.html` 与 `pages/**/*.html` 建立 SHA-256 快照，跨页逻辑只写入运行时副本，完成后验证静态输入未变化。

## 图片原型静态承载与交互门禁

整页图片原型不套用内容图图库语义匹配阶梯；文件保持本流程落盘约定，须在 `prototype/` 内离线可打开。页面内插图类内容图仍遵守 `shared-prototype-standards.md`「图片与图标」。

### 原图承载红线

- 每张输入图片对应一个独立 `pages/<name>.html`；承载页的视觉内容必须是 `pages/source-images/<image-file>` 中的完整原图。
- 承载页只允许包含必要的根容器、滚动适配容器、`<img>` 和无障碍/适配属性。绝对不得将图片 OCR、切片、解构、识别或重绘为标题、按钮、卡片、列表、导航等页面元素，也不得用新 DOM 近似复刻图片视觉。
- `pages/*.html` 不重复嵌入设备外壳；由 `index.html` 使用选中的 Manifest 设备框架加载承载页，使原图直接填充在设备屏幕区域内。
- 图片保持原始宽高比、完整显示且不得拉伸或裁剪。默认按逻辑画布宽度适配；长图放入带 `data-ycet-scroll` 的内部容器纵向滚动，文档根与设备框架不承担滚动。

### 图片处理流程

1. 执行产品端口确认门禁并等待用户明确回复。
2. 将原始整页图片保存到 `prototype/pages/source-images/`，使用清晰的 ASCII kebab-case 文件名；建立“源图片 → 承载页”一一映射，该目录不作为 `screen` 直接目标。
3. 根据已确认产品端口与宿主设备，从 Manifest 选择并复制设备框架，生成 `frame-config.json`。
4. 为每张图片生成对应的原图承载型 `pages/**/*.html`，再生成使用设备框架加载所有承载页的 `index.html`。必须先完成这两类静态文件，禁止同时生成交互入口。
5. 验证图片未被元素化重构、未被裁剪或拉伸，长图内部滚动可用，`pages/**/*.html` 与 `index.html` 可在本地和静态服务器打开；记录图片导入、承载页面、框架与配置写入。
6. 静态文件完成后停止任务，向用户展示页面清单与 `index.html`，并单独询问是否确认生成 `prototype.html`。任务开始时的交互要求不算本步骤确认。
7. 用户明确确认前，禁止生成 `prototype.html`、版本化 `prototype*.html`、`runtime-pages/` 或交互热点。
8. 用户明确确认后才读取并执行功能三：首次生成 `prototype.html`，已存在时按功能三版本规则生成下一版本。运行时副本必须继续以完整原图为视觉基底；如需交互，只能按已确认流程在 `runtime-pages/` 叠加不改变视觉的交互热点，不得把图片替换为重构 DOM。功能三结束后验证原 `pages/**/*.html` 与 `index.html` 的 SHA-256 未变化。

## 迁移规则

- 框架负责系统 UI，页面只保留产品 UI。
- 新入口使用 `data-ycet-frame-id` 与 `?screen=pages/<file>.html`。
- 迁入 `pages/` 的 HTML 必须重写所有受目录层级变化影响的本地资源引用；不得只修图片和图标。
- 页面根画布和安全区域读取项目配置。
- 只复制选中框架，所有路径保持项目内相对。
- 不得擅自重写业务文案或页面流程；HTML 分支的视觉风格只按功能一阶段二的用户确认结果实现。
- 图片分支始终保留完整原图作为页面视觉，不适用 HTML 元素化重构。
- 原型已使用新框架且配置有效时，不重复迁移。

## 完成标准

- HTML 或图片原型已纳入标准 `prototype/` 结构。
- 用户已明确回复产品端口；所选框架与功能一的 Manifest 端口映射一致，未使用原型内容或既有配置替用户判断。
- HTML 分支已从源码和关联文件直接生成并确认 `prototype/docs/Spec.md`，未调用 `brainstorming-solo` 或 `grill-me`；UI 方向与静态实现均按功能一门禁完成。
- HTML 静态产物完成后已停止；若已生成交互 Demo，存在静态完成后的用户明确确认，且功能三 SHA-256 复核通过。
- 图片分支已先生成一一对应的原图承载型 `pages/**/*.html` 与 `index.html`，没有把图片解构为页面元素。
- 图片分支生成 `prototype.html` 或版本化 Demo 前已取得静态完成后的用户明确确认；交互只存在于运行时副本。
- 项目配置、框架、入口和页面一致。
- 系统 UI 无重复，页面在框架中完整显示。
- 外链内容图与远程图标已本地化，或已记录用户明确例外。
- 无灰色占位/图标冒充内容图；断网后资源仍可显示。
- Level 1/2/3 变更未越权。
- 当前阶段允许执行的用户编辑已完成；尚未确认功能三时，跨页交互必须明确标记为待继续，不得把静态完成宣称为交互完成。
- EditLog 分别记录迁移与编辑。
- 本地 HTML、静态服务器和目录迁移测试通过。

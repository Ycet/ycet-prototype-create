# 目标

在 `outputs/skills/ycet-prototype-create/` 的实际交付基线上，为功能一至五接入项目级本地可视化编辑器工作台。工作台负责浏览、选择、批注、预览级属性修改、标准化变更包、结果展示和最近一次安全撤回；Agent 仍是唯一可在“发送给 AI”后修改源文件的一方。

# 必须遵守的边界

- 实现范围以已批准规格为唯一产品事实来源；先检查交付目录、现有 Skill 路由、共享规范和守卫脚本，再决定最小实现方式。
- 本地服务只绑定本机地址，并以项目根为实例边界。健康实例必须复用；用户手动关闭后，不得擅自重启。
- 服务只能读取已登记的项目内 HTML、其必要本地依赖和用户显式添加的外部 HTML；左栏“删除”只能移出工作区，绝不能删除磁盘文件。
- 未发送的批注、属性差异、图片替换和 `同步 pages` 只存在于当前浏览器会话；切换文件时保留，关闭工作台或成功发送后清空，不写入 `workspace.json`。
- 编辑器覆盖层、预览补丁、元素选择、嵌套 iframe 中继和 `srcdoc` 注入均不得写回源 HTML。只有变更包被 Agent 成功执行后才能更新文件。
- 变更包必须携带文件摘要、定位指纹、来源和依赖关系；摘要、路径或元素定位不匹配时必须拒绝猜测性写入。
- 项目内普通修改遵守 `EditLog.md` 规则；外部 HTML 不写永久执行历史；最近一次成功批次的撤回事务仅保存于 `.ycet-editor/undo/latest/`，并以修改后摘要校验。
- `runtime-pages` 的 `同步 pages` 只能在发送后执行，必须在暂存副本中保留或重新生成功能三消息协议，并验证 `prototype.html` 交互仍可用。
- 功能五打包前必须阻止影响打包输入的未发送草稿；打包期间使用临时锁串行化 Agent 写入。工作台不得改变 `prototype/` 中任何既有输入或 `EditLog.md`，打包器只允许原子新增一个递增 `prototype-mobile*.html`。
- 打包后的离线单文件可作为独立工作区文件编辑，但不得反向同步到运行时页。其普通编辑需要通过手机版守卫并按普通项目修改记录 `EditLog.md`；功能五自身仍是唯一不写 `EditLog.md` 的流程。

# 明确不要做的事

- 不改为浏览器扩展、Electron/Tauri、云端服务或特定 Agent 会话的直接控制器。
- 不实现图片生成、修图、抠图或“图片编辑”能力；V1 只支持图片替换和预览。
- 不持久化未发送草稿，不把工作台运行时注入物写入源 HTML，也不将预览 DOM 当作打包输入。
- 不修改功能三受保护的 `index.html`、静态 `pages/**/*.html`，或以简单覆盖方式同步 `runtime-pages`。
- 不在功能五中自动发送草稿、自动重打包、覆盖历史离线单文件，或借由编辑器绕过其 SHA-256 只读门禁。
- 不删除、移动或重命名用户的原型文件，不扩大外部文件可读写范围，也不改动本轮之外已有工作区变更。
- 不顺带重构 Manifest、设备框架、现有原型生成逻辑或无关 Skill 文档。

# 建议执行顺序

1. 复核实际交付 Skill 的目录、路由和功能一至五的写入点，确定工作台安装位置、启动入口和最小本地运行时；同时建立服务健康探测与项目级工作区配置的边界。
2. 实现本地服务、工作区注册、受限文件路由和文件监听。先验证空工作区、项目扫描、外部文件显式添加、目录分组、排序持久化和“移出不删除”。
3. 实现三栏界面及预览运行时：普通 HTML、设备框架双层 iframe 和功能五 `srcdoc` 都能选择真实元素；草稿仅覆盖预览，支持批注、缩放、设计/内容/CSS 属性、图片替换、清空当前文件修改和文件切换保留。
4. 实现标准化批量变更包、Agent 执行指令、逐项结果面板、摘要并发保护和最近一次安全撤回。先覆盖独立文件部分成功和外部文件不写永久历史，再接入 `同步 pages` 的依赖组与运行时消息验证。
5. 将统一的“确保服务可用并增量同步”接入功能一至四：功能一的设计方向与静态页、功能二的扫描和空工作区、功能三的运行时页与 Demo、功能四的迁移产物。任何生成过程不得改变原有确认门禁或静态输入保护。
6. 接入功能五：在运行时准备或离线打包后同步新增文件；打包前检查相关草稿，打包时启用锁，完成后只展示新增离线文件。离线成品的后续普通编辑必须走独立变更包和手机版守卫，且不得触发反向同步或自动再打包。
7. 逐层验证：先运行已有静态、运行时、图片和手机版守卫，再验证工作台服务生命周期、预览注入、变更包执行、撤回、功能五只读集合，以及 Chrome、Edge、Firefox 的实际交互和布局。

# 关键依赖与前置条件

- `outputs/skills/ycet-prototype-create/` 是唯一实际交付基线；`README.md`、`SKILL.md`、五个功能文档、`shared-prototype-standards.md`、`shared-editlog-rules.md` 和现有守卫脚本必须保持一致。
- 功能三已有的静态输入 SHA-256 保护、`ycet-prototype` 消息协议、运行时副本命名和 Demo 专用框架兼容规则不可回退。
- 功能五已有的确定性打包器、全项目输入 SHA-256、递增输出命名、原子落盘和离线守卫不可由工作台替代或绕过。
- 本地运行所需的运行时、依赖管理方式和测试工具必须先从现有项目配置与系统可用环境确认；若确实需要新增依赖，须最小化、记录并提供可重复安装方式。
- Chrome、Edge、Firefox 可用于工作台验证；移动真机验证仍按功能五现有规则单独标记，不得以桌面移动视口替代。
- 用户实际点击“发送给 AI”仍是修改权限的唯一入口；无实时桥接时，用户向当前 Agent 提交工作台生成的执行指令。

# 验收标准

- 功能一至五在服务健康时复用同一项目实例，在未运行时按需启动；自动打开浏览器失败时能返回可访问的本地 URL，用户手动关闭后不自启。
- 工作台能扫描并展示约定 HTML，正确处理目录自动分组、手动分组、排序、外部文件、缺失文件和根级 `prototype-mobile*.html`；磁盘文件不因工作台移除操作而变化。
- 普通页面、双层 iframe 和功能五离线 `srcdoc` 中的真实组件都能被选中，批注、缩放和属性预览不写源文件；未发送草稿不会跨重启恢复。
- “发送给 AI”以一个批次聚合全部会话修改，发送后清空全部草稿；Agent 能以文件摘要和元素指纹定位目标，允许独立文件部分成功，并同时在回复和结果面板报告原因。
- “清空修改”仅影响当前文件属性差异和待发送同步操作，保留批注；`同步 pages` 仅在发送后执行，并在静态页与运行时页依赖组中验证既有交互。
- 最近一次成功修改可跨工作台重启撤回；发生后续外部变更时安全拒绝，且不影响不相关文件。
- 功能五有相关未发送草稿时拒绝打包；无草稿时只生成一个递增离线文件，既有 `prototype/` 输入和 `EditLog.md` 保持字节不变，成功文件自动加入工作区。
- 离线成品的普通编辑不会修改运行时源页或自动生成新包，且必须通过手机版守卫；功能五打包本身不写 `EditLog.md`。
- 所有新增或修改的 Skill 文档、启动器、服务、变更包处理和验证脚本符合现有目录与中文注释约定；Chrome、Edge、Firefox 中不引入布局破坏、不可滚动、无法选中或跨页消息回归。

# 风险与回退注意

- 任意 HTML 的 DOM 与嵌套 iframe 结构不同。定位失败、注入跨域受限或 `srcdoc` 不可访问时应保持只读预览并报告，不可猜测修改目标或降级为写源文件。
- 文件监听、多个 Agent 和功能五打包可能并发改变摘要。使用每批次摘要校验、打包锁和原子提交；冲突时不写该文件或依赖组，并刷新后重试。
- `同步 pages` 可能破坏运行时跨页逻辑。始终在暂存副本中合并，保留功能三注册表和消息中继；验证失败即放弃该组。
- 直接编辑离线单文件可能破坏其自包含结构。以手机版守卫作为写入门槛；失败时保留原文件与草稿说明，建议编辑源运行时页后重新调用功能五。
- 回滚可能遇到用户或其他 Agent 的后续写入。只在摘要仍匹配时恢复；不匹配时报告冲突，绝不强制覆盖。
- 服务故障、端口占用或浏览器无法自动打开时，不影响已生成原型；返回 URL 或诊断信息，且不写入源页面作为替代。

# 完成定义（Definition of Done）

后续 Agent 可以将工作视为完成，必须同时满足：实际交付 Skill 已按规格接入功能一至五；本地工作台、变更包和回滚行为可用；所有现有静态、运行时、图片与功能五守卫持续通过；新增的工作台验证覆盖服务复用、草稿生命周期、嵌套预览、部分成功、运行时同步、撤回及功能五只读打包；Chrome、Edge、Firefox 的结果和未完成的移动真机验证均如实记录。任何一项保护边界、守卫或浏览器验证未通过，均不应宣称完成。

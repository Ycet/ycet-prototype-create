# 实施结果

- 功能五路由、默认选项 E、流程文档、共享规范和 Codex 展示元数据已更新。
- 已新增确定性打包器、移动文件守卫、14 条行为评估用例、打包器回归测试和真实浏览器移动视口测试。
- 功能一至四共用的五类 Manifest 框架已在 Chrome、Edge 中回归通过。
- 功能五离线单文件已在 Chrome、Edge 的竖屏/横屏、项目外中文空格目录和断网状态下通过；Firefox 因当前环境 `spawn EPERM` 未运行，移动端真机未验证。

# 目标

在不改变功能一至功能四既有行为的前提下，为 `ycet-prototype-create` 增加功能五：把已确认的多页面运行时原型打包成可单独发送到手机、脱离项目目录且断网可运行的 `prototype-mobile*.html`。

后续实现必须同时交付功能路由、功能五流程文档、确定性单文件打包能力、只读保护、自动测试和可验证的移动端预览行为。

# 必须遵守的边界

1. 以已批准规格 `../specs/2026-07-18-ycet-prototype-create-mobile-single-file-spec.md` 为唯一需求依据；发现冲突时停止并请求用户修订规格，不自行扩展。
2. 保持功能一至功能四的路由、确认门禁、产物、框架、路径和交互协议兼容。
3. 功能五首次输出 `prototype-mobile.html`，后续输出 `prototype-mobile-vN.html`，不得覆盖已有版本。
4. 已有 `runtime-pages/*.html`、`pages/*.html`、`index.html`、`prototype.html`、框架、配置和资源文件均为只读输入；建立文件集合与 SHA-256 基线并在生成后复核。
5. 只有完全没有可用运行时页面且用户已明确确认跳转逻辑时，才允许新建 `runtime-pages/`。部分存在、目标悬空或来源冲突时必须停止。
6. 运行时准备只能创建缺失时的全新运行时页面，不得创建或修改 `prototype.html`。
7. Skill 负责路由、交互确认、运行时准备和验收门禁；专用确定性脚本只负责读取已准备输入、内联资源、构建移动端外壳、选择版本和原子写入最终文件。
8. 最终手机版文件必须完全自包含。禁止残留项目相对资源读取、绝对路径、`file:///`、HTTP/HTTPS、CDN 或其他网络启动依赖。
9. 页面仍通过功能三 `ycet-prototype` 消息协议导航；不得另建与功能三不兼容的协议。
10. 手机端默认全屏显示内嵌页面，不显示设备外壳、常驻导航或调试信息；只允许通过预览按钮展开覆盖式左侧页面导航。
11. 无法完整解析、内联或验证的关键依赖必须阻断生成，不得静默删除功能、替换占位、保留网络依赖或声称完成。
12. 修改关键 Python 代码时添加必要的中文注释，保持现有代码风格，避免无关重构。
13. 现有工作区改动属于用户；不得恢复、删除、格式化或混入与功能五无关的文件。

# 明确不要做的事

- 不修改功能三桌面 Demo 的布局和交互行为来迁就功能五。
- 不把 `runtime-pages/`、图片、字体或脚本复制到手机版旁边作为隐含依赖。
- 不把多个运行时页面直接合并到同一 DOM，造成 CSS、ID 或全局脚本冲突。
- 不依赖 Blob URL 作为核心页面加载方案；已确认方案为全屏 `iframe srcdoc`。
- 不在单文件打包脚本中推测业务流程、创建运行时页面、执行用户脚本或访问网络。
- 不为部分运行时页面自动生成缺失页，不混合不同来源的交互逻辑。
- 不覆盖 `prototype-mobile.html` 或任何历史手机版本。
- 不设置未经实际验证的固定文件大小阈值，也不以压缩体积为由减少页面或资源。
- 不把桌面移动视口模拟结果冒充 Safari iOS 或 Android 真机验证。
- 不自动执行 Git add、commit、merge、push、发布或部署。

# 建议执行顺序

1. 重新读取 README、当前 `SKILL.md`、功能三、共享规范、EditLog 规则、Manifest、现有守卫和测试；记录当前分支与脏工作区，确认功能五改动范围。
2. 运行现有结构、守卫和框架回归测试，记录功能一至功能四基线。既有失败须先分类，不得通过功能五改动掩盖。
3. 为功能五建立行为测试样本，覆盖完整产物、仅运行时页面、仅 `prototype.html`、两者缺失、部分缺失和冲突状态；先让新增测试准确暴露缺失能力。
4. 更新 Skill 路由、默认选项 E、功能五全局边界和渐进读取入口；新增功能五流程文档，并同步共享规范与 EditLog 规则。
5. 实现专用确定性打包器：输入审计、注册表提取、初始页选择、递归资源图、MIME 识别、资源去重、安全转义、`srcdoc` 页面数据、移动端外壳、版本选择和原子输出。
6. 实现手机端运行外壳：全屏页面容器、菜单按钮、左侧导航抽屉、消息来源与目标校验、页面历史和浏览器返回处理。
7. 扩展只读守卫和结构校验器，确保打包器不修改输入，最终文件无外部依赖，功能五文档、脚本和测试均存在且包含关键门禁。
8. 增加自动回归测试，覆盖资源内联、危险文本转义、路径安全、版本递增、生成失败无半成品、目录迁移、断网和页面交互。
9. 运行功能一至功能五的结构与回归测试；对可用浏览器执行移动视口运行时检查。无法执行的真机浏览器明确记录未验证。
10. 更新根 README 中的功能范围、使用方式、验证命令、目录结构和已知限制；审阅最终差异，确保没有无关文件、生成缓存或既有输入变更。

# 关键依赖与前置条件

- 已批准需求规格存在且状态为 `approved`。
- Python 3 可用，现有 Skill 校验器与守卫可运行。
- 功能三运行时页面命名、页面注册表、消息协议和只读保护规范保持有效。
- Manifest、框架路径白名单和 `runtime-pages/` 契约保持有效。
- 测试样本包含可内联的 CSS、JavaScript、图片、图标、字体，以及可验证的多页面跳转。
- 实现前确认是否引入第三方打包依赖。优先使用现有依赖或 Python 标准库；新增依赖必须说明必要性、许可、离线可用性和安装前置条件。
- 浏览器运行时测试至少能在当前环境可用的 Chromium 系浏览器执行；Safari iOS 和 Android 真机结果不可伪造。
- 仓库既有 `evals/evals.json` 缺失等已知失败须单独记录，不能归因于功能五。

# 验收标准

1. `SKILL.md` 能按明确手机预览意图直接路由到功能五，默认选择菜单包含选项 E。
2. 功能五文档完整描述五类输入状态、确认门禁、运行时准备、单文件打包、版本、异常和完成标准。
3. 专用打包器只读取准备完成的运行时页面和相关资源，只写一个新的 `prototype-mobile*.html`。
4. 完全缺少运行时页面时，只有在确认后才创建全新运行时页面；部分或冲突输入会阻断。
5. 首次和重复生成遵守 `prototype-mobile.html`、`prototype-mobile-vN.html` 递增规则，不覆盖旧版本。
6. 最终文件使用一个全屏 `iframe srcdoc`，默认隐藏设备框架、常驻导航和调试信息。
7. 菜单按钮、覆盖式左侧抽屉、页面名称、顺序、当前页高亮和关闭行为可用。
8. 原型内部 `navigate`、抽屉切换、内部历史和浏览器返回行为符合规格。
9. CSS、脚本、图片、图标、字体和必要资源完全内联，无项目路径、绝对路径、远程 URL 或 CDN 残留。
10. 中文、空格、query/hash、危险 `</script>` 内容、引号、反斜杠和 Unicode 分隔符得到安全处理。
11. 生成失败不留下半成品；生成前后受保护输入文件集合和 SHA-256 不变。
12. 单个输出文件复制到带中文和空格的项目外目录后可打开，断网后全部页面和交互仍可用。
13. 自动测试覆盖已批准规格中的输入矩阵、资源、路径、安全、版本、只读和交互要求。
14. 当前环境可运行的结构、守卫和浏览器测试通过；未验证真机目标被明确列出。
15. README、共享规范、EditLog 规则和结构校验器与实际实现一致。

# 风险与回退注意

- 资源内联可能显著增加文件大小和内存占用。若目标浏览器不稳定，先报告具体资源和规模，不删除功能或降低完整性。
- `srcdoc` 切换会销毁页面瞬时 DOM 状态；不要额外实现未经规格确认的页面状态缓存。
- JavaScript 模块、CSS `@import`、字体和动态资源路径是最容易遗漏的依赖面，应通过资源图和失败用例验证。
- 外层数据必须安全转义，避免内嵌页面内容提前结束 `<script>` 或破坏 JSON。
- `file://`、History API、`postMessage` 和大文件在移动浏览器上的行为存在差异；桌面通过不等于真机通过。
- 若新增实现导致功能一至功能四回归，停止扩展功能五并修复本次改动，不修改既有规范规避测试。
- 若打包器无法确定页面注册表、初始页或 MIME 类型，停止并保留已有文件，不生成猜测结果。
- 回退时只撤销功能五新增或本轮修改内容；不得影响用户已有工作区改动或已交付原型。

# 完成定义（Definition of Done）

满足以下全部条件后，后续 Agent 才能将功能五视为完成：

- 路由、选项 E、功能五文档、专用打包器、守卫、测试、共享规范、EditLog 和 README 已一致更新；
- 五类输入状态和所有确认门禁均有自动或可重复人工验证证据；
- 真正离线单文件可以在项目外、断网环境中运行所有登记页面和交互；
- 手机端全屏、菜单按钮、左侧抽屉、消息导航和返回历史符合批准规格；
- 已有原型文件和功能一至功能四行为未发生回归；
- 失败场景不会覆盖已有版本或留下半成品；
- 结构、守卫、打包器和可用浏览器测试通过；
- 真机未验证项、文件规模和已知限制在完成说明中如实列出；
- 最终差异只包含功能五所需变更，没有生成缓存、无关重构或用户文件回退。

# 功能四：现有 HTML 或图片原型规范化与编辑

## 目标

接管非本 Skill 生成的 HTML 或图片原型，按 Manifest 驱动的新框架体系审计、分级规范化，再执行用户要求的编辑。原有 Level 1/2/3 门禁保持不变。

开始前读取 `shared-prototype-standards.md`、`shared-editlog-rules.md` 与 `../assets/frames/manifest.json`。

## 输入类型

| 输入 | 处理方式 |
| --- | --- |
| HTML 原型 | 合规审计 → 建议重构等级 → 用户确认 → 规范化 → 用户编辑 |
| 图片原型 | 导入资源 → 确认命名 → 选择端口框架 → 生成承载页面与入口 |

## HTML 审计

检查：

- 是否位于 `prototype/` 结构内；
- 是否存在独立 `pages/` 页面；
- 是否存在 `frame-config.json`；
- 项目配置、`index.html` 和 Manifest 是否一致；
- 框架文件是否存在并支持 `screen` 协议；
- 页面根画布是否匹配逻辑尺寸；
- 页面是否重复绘制系统 UI；
- 安全区域、滚动容器和产品固定导航是否合理；
- iframe 是否溢出、裁剪、留白或出现原生滚动条；
- `index.html` / 设计预览中框架 iframe 是否等于项目 `preview` 固定像素，是否被百分比或二次 scale 压扁；
- 是否存在外链内容图（如 `img[src^="http"]`）或 CSS 远程内容背景图；
- 是否存在远程图标 CDN / 远程 SVG 图标依赖；
- 是否用灰色占位或图标冒充内容图；
- 本地图片/图标相对路径是否指向存在文件；
- 本地样式、脚本、字体、`srcset`、CSS `url()` / `@import` 和模块 import 是否在迁移后仍指向存在文件；
- 是否存在 EditLog。

### 新框架配置异常

- 配置缺失：从 `index.html`、框架文件名和 Spec 推导候选值，向用户确认后补齐。
- 配置无效或与 `index.html` 冲突：列出差异，不静默覆盖。
- Manifest 或框架文件缺失：报告并停止新框架迁移。

### 旧框架

识别 `.phone-frame`、`.android-frame`、`.miniapp-frame`、`.browser-frame`、`.desktop-frame` 等旧结构。旧尺寸只用于理解当前页面，不写入新 Manifest。

## 分级重构

| 等级 | 适用情况 | 允许动作 |
| --- | --- | --- |
| Level 1 轻量接管 | 页面视觉和结构基本正常 | 迁入 `pages/`，按迁移前后的文件位置重写本地资源相对路径，根据端口按需复制框架，补齐 `frame-config.json` 与 `index.html` |
| Level 2 结构修复 | iframe 不稳定或系统 UI 重复 | 修复逻辑画布、滚动、安全区域、系统/产品 UI 边界和新框架引用 |
| Level 3 规范化重写 | 严重不合规或无法稳定迁移 | 保持内容、文案和功能表达不变，重写 HTML/CSS |

Level 3 必须先获得用户确认。

## HTML 处理流程

1. 完成审计并展示证据。
2. 建议最低必要重构等级。
3. 用户确认等级；Level 3 未确认不得继续。
4. 从 Manifest 选择端口框架，按需复制并生成项目配置快照。
5. 规范化页面与入口，不改变未授权内容；移动 HTML 前以原文件 URL 为基准解析本地 `src`、`srcset`、`href`、CSS `url()` / `@import` 和模块 import，移动后按新文件位置重写为项目内相对路径并逐项验证存在；同时将外链内容图下载到 `assets/images/`、远程图标下载到 `assets/icons/`。无法下载时按近似图顶替/语义阶梯处理，仍失败则暂停报告。
6. 执行用户明确要求的编辑。
7. 分别记录“规范化重构”和“用户要求的编辑”；资源本地化与降级一并记入 EditLog。

## 图片原型流程

整页图片原型不套用内容图图库语义匹配阶梯；文件保持本流程落盘约定，须在 `prototype/` 内离线可打开。页面内插图类内容图仍遵守 `shared-prototype-standards.md`「图片与图标」。

1. 将原始整页图片保存到 `prototype/pages/source-images/`，文件名使用清晰英文名；该目录是功能四图片原型的兼容资源目录，不作为 `screen` 直接目标。
2. 提醒用户改为清晰英文文件名，并等待确认。
3. 确认产品端口与宿主设备，从 Manifest 选择框架。
4. 按需复制框架并生成 `frame-config.json`。
5. 在 `prototype/pages/` 生成同语义英文名的独立承载 HTML，在页面中使用 `source-images/<image-file>` 引用原图，并生成 `index.html`。
6. 图片完整展示，不被裁剪且无无意义留白；长图在框架内部纵向滚动。
7. 记录图片导入、承载页面、框架和配置写入。

## 迁移规则

- 框架负责系统 UI，页面只保留产品 UI。
- 新入口使用 `data-ycet-frame-id` 与 `?screen=pages/<file>.html`。
- 迁入 `pages/` 的 HTML 必须重写所有受目录层级变化影响的本地资源引用；不得只修图片和图标。
- 页面根画布和安全区域读取项目配置。
- 只复制选中框架，所有路径保持项目内相对。
- 不为了迁移顺手重写业务文案、视觉风格或页面流程。
- 原型已使用新框架且配置有效时，不重复迁移。

## 完成标准

- HTML 或图片原型已纳入标准 `prototype/` 结构。
- 项目配置、框架、入口和页面一致。
- 系统 UI 无重复，页面在框架中完整显示。
- 外链内容图与远程图标已本地化，或已记录用户明确例外。
- 无灰色占位/图标冒充内容图；断网后资源仍可显示。
- Level 1/2/3 变更未越权。
- 用户要求的编辑已完成。
- EditLog 分别记录迁移与编辑。
- 本地 HTML、静态服务器和目录迁移测试通过。

# 功能五：移动端离线单文件原型

## 目标

根据已确认的 `prototype/runtime-pages/**/*.html` 生成可单独发送到手机、脱离项目目录且断网运行的 `prototype-mobile.html` 或递增版本。手机版复用功能三的页面注册表、页面跳转逻辑和 `ycet-prototype` 消息协议，但不显示桌面 Demo 的左侧常驻导航、设备外壳或调试信息。

开始前读取：

- `shared-prototype-standards.md`；
- `function-3-interactive-demo.md` 中的运行时页面、双路径注册表、规范目标和消息协议；
- `shared-editlog-rules.md` 中的功能五只写例外。

## 强制边界

1. 功能五是独立功能。缺少运行时页面时仍在功能五内部完成运行时准备，不切换为功能三。
2. 已存在的 `runtime-pages/**/*.html`、`pages/**/*.html`、`index.html`、`prototype.html`、`prototype-vN.html`、框架、资源、配置、Spec 和 EditLog 均为只读输入。
3. 打包阶段只允许新增一个 `prototype-mobile*.html`；不得格式化、补写、修复、重命名、删除或覆盖任何既有文件。换言之，打包阶段只新增一个手机版文件，不得修改 EditLog 或其他项目文件。
4. 只有完全没有运行时 HTML 且用户明确确认页面跳转逻辑后，才可创建一组全新的 `runtime-pages/**/*.html`。不得覆盖已有运行时页，也不得混合不同来源或版本。
5. 最终文件必须完全自包含。禁止残留本地相对资源读取、绝对路径、`file:///`、HTTP/HTTPS、CDN、登录态或服务器依赖。
6. 无法完整解析、内联或验证时停止，不得删除功能、替换占位或保留网络依赖后声称完成。
7. 不创建或修改 `prototype.html`，不绘制设备框架，不把多个页面合并进同一 DOM。

## 输入审计与确认门禁

先只读检查 `runtime-pages/`、`prototype.html`、静态页、Spec、页面目标和资源，不得执行页面脚本。

| 运行时页面 | `prototype.html` | 处理方式 |
| --- | --- | --- |
| 完整有效 | 完整有效 | 以 `prototype.html` 的页面注册表、顺序和目标映射为主，核对运行时页后直接打包，不再询问跳转逻辑 |
| 完整有效 | 不存在 | 从同一版本的运行时页、`data-ycet-nav-target`、`navigate` 消息和标题推导注册表，直接打包 |
| 不存在 | 存在 | 展示从注册表和静态输入推导的页面跳转图；获得用户明确确认后创建全新运行时页，再打包 |
| 不存在 | 不存在 | 从 `pages/**/*.html`、Spec 和当前对话整理页面跳转图；获得用户明确确认后创建全新运行时页，再打包 |
| 部分存在、目标悬空、多个版本或来源冲突 | 任意 | 停止并列出文件、目标和冲突，不自动补齐或选择其中一方 |

“完整有效”必须同时满足：

- 每个登记运行时路径都存在且位于 `runtime-pages/`；
- 所有跨页目标都能映射到同一注册表；
- 无远程、绝对、上级目录或 `javascript:` 目标；
- 缺少 `prototype.html` 时，`runtime-pages/` 只包含一个可唯一识别的 Demo 版本；
- 能按下文优先级得到唯一初始页面。

## 完全缺失时的运行时准备

只在输入审计判定“完全没有运行时 HTML”后执行：

1. 从 `prototype.html`，或从静态页、Spec 与当前对话，整理页面、入口和跳转图。
2. 向用户展示跳转图并获得明确确认；用户确认前不得创建 `runtime-pages/`。
3. 对所有既有项目文件建立原始字节 SHA-256 和相对路径集合基线。
4. 复用功能三的运行时副本命名、双路径注册表、规范目标和消息协议，一次性创建完整运行时页集合。
5. 不创建 `prototype.html`，不修改静态页、入口、框架、资源或配置。
6. 复核既有输入文件集合和 SHA-256；不一致时停止并报告，不得重算基线掩盖变化。
7. 运行时准备通过后，重新建立打包阶段的全项目只读基线。

如果 `runtime-pages/` 已有任意 HTML，禁止进入本节流程。

## 页面注册表与初始页

每项至少包含稳定页面 ID、显示名称、静态 pathname、运行时 pathname、顺序、初始页标记、已登记目标和自包含 `srcdoc` 数据。

初始页按以下优先级选择：

1. `prototype.html` 明确登记的初始页面；
2. `prototype.html` 注册表中的第一个有效运行时页面；
3. 文件名对应 `home` 的运行时页面；
4. 只有一个来源和版本时，运行时注册表的第一个页面。

存在多个显式初始页、无法唯一识别版本或无法得到有效初始页时停止。

## 离线打包

开始打包前读取 `shared-workbench-protocol.md`，先运行 `prototype_workbench.py lock acquire --project-root <项目根目录>`。健康工作台对本次打包输入存在未发送草稿时必须阻止打包，要求用户先发送或清空；不得自动发送、清除或把预览草稿混入输入。获取成功后保存锁令牌，并在成功、失败或取消的 `finally` 路径运行 `lock release`。锁期间工作台只读预览，不接受新的变更包。

使用确定性脚本，不手写或临时拼接单文件：

```text
python <skill目录>/scripts/build_mobile_prototype.py --prototype-dir <prototype目录>
```

脚本只负责：

- 读取已准备完成的运行时页面和有效注册表；
- 递归解析并内联本地 CSS、`@import`、`url()`、JavaScript、静态模块依赖、图片、`srcset`、SVG、图标、字体和可枚举资源；
- 阻断缺失资源、远程依赖、路径越界、无法枚举的动态 import/fetch 和网络 API；
- 将每个页面转为独立 Base64 `srcdoc`，避免 CSS、DOM ID 和全局脚本冲突；
- 生成全屏 iframe、菜单按钮、覆盖式左侧导航抽屉、目标白名单和历史管理；
- 首次选择 `prototype-mobile.html`，后续选择 `prototype-mobile-v2.html`、`prototype-mobile-v3.html` 等下一个版本；
- 在临时文件完成机械校验后原子落盘，并复核输入文件集合与 SHA-256。

脚本不得推测业务流程、创建运行时页面、执行用户页面脚本、访问网络、修改输入或更新 EditLog。失败不得留下最终文件或覆盖已有手机版本。

## 手机端外壳与交互

- 使用一个无边框 `iframe srcdoc` 铺满浏览器可视区域，提供 `100vh` 回退并优先使用 `100dvh`。
- 默认只显示产品页面，不显示设备框架、常驻页面导航或调试信息。
- 左上角菜单按钮位于预览工具层，可展开覆盖式左侧导航抽屉；抽屉显示页面顺序、名称和当前页高亮，不显示路径或日志。
- 选择页面、点击遮罩、点击关闭按钮或按 Escape 后关闭抽屉，不缩放当前页面。
- 页面内滚动、弹窗、表单和其他页面内交互继续由当前运行时页面处理。
- 运行时页继续发送 `channel: "ycet-prototype"`、`version: 1`、`type: "navigate"`；外层同时验证 `event.source`、消息字段和页面注册表。
- 合法目标可携带 query/hash；先按解码后的规范 pathname 命中注册表，再保留 query/hash。拒绝远程 URL、绝对路径、上级目录、控制字符、`javascript:` 和未登记目标。
- 抽屉选择与原型内部跳转复用同一注册表。每次合法前进写入同文件 History；浏览器返回优先恢复上一原型页面，初始页之前交还浏览器默认行为。
- 页面切换会重建 `srcdoc`，不承诺恢复已销毁页面的瞬时 DOM 状态。

## 输出与只读门禁

打包前后的受保护集合是 `prototype/` 下当时已经存在的全部文件，包含全部历史 `prototype-mobile*.html`。只排除：

- 本次临时构建文件；
- 本次开始时尚不存在、最终新增的一个手机版文件。

脚本内部执行全集合 SHA-256 保护。不得在成功后追加 EditLog，因为这会违反“只新增一个手机版文件”的强约束；将构建信息写入最终完成说明。

确定性打包和全部守卫通过后，调用 `prototype_workbench.py sync --project-root <项目根目录> --add <新增prototype-mobile绝对路径>`。只同步本次新增文件；健康实例存在时不重启，实例不存在时按统一协议启动。不得同步草稿到运行时页、修改旧离线版本或自动触发下一次打包。

## 验证

先运行确定性回归与移动文件守卫：

```text
python <skill目录>/scripts/test_build_mobile_prototype.py
python <skill目录>/scripts/prototype_guard.py mobile --prototype-dir <prototype目录> --mobile-file <生成文件>
python <skill目录>/scripts/test_mobile_prototype_runtime.py
```

再对当前环境可用的浏览器执行移动视口验证，至少检查：

1. 初始页铺满视口，竖屏和横屏无外层滚动条；
2. 菜单、抽屉、遮罩关闭、当前页高亮和直接选页可用；
3. 原型内部 `navigate`、query/hash、前进和浏览器返回可用；
4. 图片、字体、样式、脚本、弹窗、表单、滚动和图片热区可用；
5. 最终文件复制到带中文和空格的项目外目录后可直接打开；
6. 断网后全部登记页面和交互仍可用。

桌面移动视口不能冒充 Safari iOS、Chrome Android 或 Edge Android 真机结果。未实际运行的浏览器必须标为“未验证”。

## 失败条件

出现以下任一情况立即停止：

- 运行时页面部分缺失、目标悬空、多个版本或来源冲突；
- 需要确认的跳转图尚未获得确认；
- 无法确定唯一初始页；
- 页面或资源路径越界、资源缺失或 MIME 无法确定；
- 存在远程资源、动态网络、登录态、真实后端或无法枚举的动态依赖；
- 生成前后受保护输入的相对路径集合或 SHA-256 不一致；
- 临时构建、输出版本选择、原子写入或最终机械校验失败；
- 当前目标浏览器无法稳定加载最终文件。

失败时保留既有手机版本和只读输入，删除本次临时文件，不生成占位或半成品。

## 完成标准

- 新增且只新增一个正确递增的 `prototype-mobile*.html`；没有覆盖旧版本。
- 页面、样式、脚本、图片、图标、字体和必要资源均在文件内部，无本地或网络运行依赖。
- 每个页面在独立全屏 `srcdoc` 中运行；菜单按钮和覆盖式导航抽屉可用。
- 原型内部跳转、直接选页和浏览器返回复用功能三协议并通过白名单校验。
- 既有输入文件集合与 SHA-256 完全不变，失败场景无半成品。
- 完成说明列出输出文件、集成页面数、内联资源数、文件大小、只读校验结果、浏览器结果、真机未验证项和已知限制。
- 打包前工作台草稿门禁与锁均已通过，锁已释放；新增离线文件已加入工作台，既有文件和 EditLog 字节未变化。
